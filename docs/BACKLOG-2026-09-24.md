### AAS-24-10 · Сортировка списка писем: по дате, новые сверху
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P1 |
| **Тип** | Feature |
| **Источник** | Продукт / UX |
| **Контекст** | Нужна явная сортировка списка; главное и по умолчанию — по дате, свежие письма сверху. |

**Требование.** В списке писем доступна сортировка. Режим по умолчанию и основной: **по дате получения/отправки, убывание (новые сверху)**. Допустимы дополнительные ключи (например отправитель, тема), если не усложняют UI.

**Критерии приёмки**
- [x] По умолчанию список отсортирован по дате, новые сверху.
- [x] Пользователь может сменить направление (новые ↔ старые) и/или ключ сортировки из UI списка.
- [x] Выбор сохраняется между сессиями (или хотя бы в рамках сессии — зафиксировать в UI).
- [x] Сортировка согласована с догрузкой страниц: при подгрузке старых писем порядок не ломается.
- [x] Работает для Bank и Seller, для обычного списка и (если включены) цепочек — поведение цепочек описано (сортировка по дате последнего письма в треде).

### AAS-24-08 · Удаление пользовательской папки (Alfa-Bank)

|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P1 |
| **Тип** | Feature |
| **Источник** | Владена Грекова |
| **Контекст** | Папка создана в AAS, в браузерный OWA не прососалась; удалить из клиента нельзя. |

**Требование.** Для пользовательских папок (не системных Inbox/Sent/…) доступно удаление через UI с подтверждением; операция уходит на сервер EAS FolderDelete (или эквивалент).

- [x] После успеха папка исчезает из дерева; при ошибке сервера — сообщение.
- [x] Если в папке есть письма — либо запрет с пояснением, либо явное «удалить вместе с содержимым» (выбрать одно поведение и зафиксировать в UI).

### AAS-24-07 · Клавиатурная навигация по списку писем + автопрочтение
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P1 |
| **Тип** | Feature |
| **Источник** | Владена Грекова |
| **Контекст** | Нет стрелок ↑/↓ между письмами; выбор письма не помечает прочитанным — только клик по точечке. |

**Требование.**
1. Стрелки ↑/↓ (и опционально j/k) перемещают фокус/выделение по списку писем и открывают превью выбранного.
2. При открытии письма в превью оно помечается прочитанным (как в Outlook), с возможностью снова пометить непрочитанным иконкой.

**Критерии приёмки**
- [x] ↑/↓ меняют письмо без мыши; превью обновляется.
- [x] Переход на непрочитанное → статус Read на сервере (или в очереди sync) без отдельного клика по точечке.
- [x] Точечка / иконка по-прежнему позволяет вручную Read ↔ Unread.
- [x] Фокус не «прыгает» со списка в композер/поиск без явного Tab.

### AAS-24-06 · Закрытие окна ≠ выход: клик по иконке снова открывает UI
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P1 |
| **Тип** | Bug / UX |
| **Источник** | Владена Грекова |
| **Контекст** | После закрытия окна клик по иконке не открывает приложение — только Quit → Launch. |

**Требование.** Закрытие главного окна оставляет процесс в menu bar; клик по иконке Dock и/или по иконке трея снова показывает главное окно.

**Критерии приёмки**
- [x] Close (красная кнопка) не завершает процесс.
- [x] Клик Dock / tray → окно на переднем плане.
- [x] Quit только через «Завершить» / Cmd+Q.
- [x] Состояние выбранной вкладки/папки сохраняется между close и reopen в рамках сессии.

### AAS-24-04 · Производительность почты при большом объёме непрочитанных
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P1 |
| **Тип** | Perf |
| **Источник** | Владена Грекова |
| **Контекст** | При 1200+ непрочитанных в Alfa-Seller UI «тупит»; Sync не помогает; рестарт частично лечит. Даже после прочтения/удаления тормоза остаются. |

**Требование.** Клиент остаётся отзывчивым при тысячах писем / непрочитанных в Seller (и Bank): список, переключение папок, Sync не блокируют UI на секунды.

**Критерии приёмки**
- [ ] Открытие Inbox с ≥1000 непрочитанных: первый экран списка < N с (зафиксировать N после замера; ориентир ≤3 с на M-серии).
- [ ] Кнопка Sync не «замораживает» окно; прогресс/статус видимы.
- [ ] После массового прочтения/удаления счётчики и список не требуют перезапуска приложения.
- [ ] Память / CPU не растут неограниченно при фоновой догрузке (пагинация / виртуализация списка).

### AAS-24-03 · Удаление письма Alfa-Bank: один клик без ложной ошибки
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P0 |
| **Тип** | Bug |
| **Источник** | Владена Грекова |
| **Контекст** | Первый «Удалить» → ошибка; повтор → «перемещено». |

**Требование.** Удаление / перемещение в «Удалённые» для писем Alfa-Bank выполняется с одной успешной попытки; при реальной ошибке — одно понятное сообщение без необходимости «нажать ещё раз».

**Критерии приёмки**
- [x] Первый клик «Удалить» либо успешно перемещает письмо, либо показывает стабильную ошибку сервера.
- [x] Нет сценария «ошибка → повтор → успех» на одном и том же письме без изменения данных.
- [x] Проверено на Bank Inbox и на письме из другой папки Bank.

### AAS-24-02 · Календарь: синхронизация не должна останавливаться после первых событий
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P0 |
| **Тип** | Bug |
| **Источник** | Иван Раченко |
| **Контекст** | После входа календарь загрузил ~3 события и остановился. |

**Требование.** Полная / инкрементальная синхронизация календаря доводит окно (день/неделя/месяц) до актуального состояния либо явно сообщает о сбое с возможностью повтора.

**Критерии приёмки**
- [x] На чистом входе после успешного auth календарь догружает события за видимый период (не «залипает» на 2–3 штуках).
- [x] При обрыве / таймауте — понятная ошибка + кнопка «Синхронизировать» продолжает с того же аккаунта.
- [x] В логе/статусе видно, какой аккаунт и на каком шаге остановился.

### AAS-24-01 · Ошибка входа: указать, какой аккаунт не принял пароль
| | |
|---|---|
| **Добавлено** | 24.09.2026 |
| **Приоритет** | P0 |
| **Тип** | Bug |
| **Источник** | Иван Раченко |
| **Контекст** | При неверном пароле одного из аккаунтов (Bank / Seller) сообщение не говорит, *какой* именно. |

**Требование.** При ошибке аутентификации EAS показывать имя/роль аккаунта (например «Alfa-Bank» / «Alfa-Seller») и, по возможности, логин (`moscow\U_…` / seller-логин), для которого отказ.

**Критерии приёмки**
- [x] Если упал только один из двух аккаунтов — в UI явно назван этот аккаунт.
- [x] Если упали оба — два отдельных сообщения или одно с перечислением.
- [x] Общая формулировка «неправильный пароль» без указания аккаунта не используется.
