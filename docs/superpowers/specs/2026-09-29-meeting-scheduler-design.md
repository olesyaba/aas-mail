# Планировщик встреч для больших групп: «Лучшие варианты» + «По людям»

Дата: 2026-09-29 · Статус: согласован в чате, ждёт ревью спецификации
Прототип: `web/prototypes/meeting-scheduler.html` (варианты C и A; B и D не берём)

## Зачем

Сейчас «Новое событие» (`web/index.html`, `eventForm`) проверяет занятость
текстом («Мария: занят») и предлагает 3 слота «свободно у всех». На встречах с
десятками участников этого мало: не видно, *кто* мешает, нельзя сравнить варианты,
нет опциональных участников и переговорок, повестка — свободный текст.

Успех: организатор встречи на 20–40 человек за одну минуту видит лучшие окна
недели с объяснением, при желании проверяет их по людям и отправляет приглашение,
где опциональные и переговорка помечены как таковые в Exchange.

## Ограничения ActiveSync (проверено по коду клиента)

- Занятость — строка `MergedFreeBusy` из `ResolveRecipients`, один символ на 30 мин:
  `0` свободен, `1` под вопросом, `2` занят, `3` вне офиса, `4` нет данных.
- Список рассылки резолвится одной записью, без состава и без занятости → строка
  «занятость не видна», раскрытия в людей нет.
- Часовых поясов участников нет → ограничение «чужие рабочие часы» не делаем.
- Каталога переговорок нет → переговорку находят поиском по каталогу, как человека,
  и помечают ролью «переговорка»; помеченные запоминаются (`prefs.rooms`).
- Seller (Stalwart) занятость других не отдаёт → вкладки показывают «на этом сервере
  занятость участников недоступна» и проверяют только свой календарь (как сейчас).

## Интерфейс

### Окно встречи
Модалка редактора становится широкой (класс `aas-modal--wide`, до 1180 px):
слева прежняя форма, справа панель с вкладками **«Лучшие варианты»** (по умолчанию)
и **«По людям»**. Ширина < 900 px: панель уходит под форму. Без участников справа
пустое состояние «Добавьте участников — покажу свободное время».
Редактирование существующей встречи работает так же.

### Участники
Поле `#eatt` заменяется тремя группами плашек: **Обязательные**, **Опциональные**,
**Переговорки** + общее поле ввода с подсказками из каталога (`bindPeopleInput`).
Enter — в обязательные, Shift+Enter — в опциональные. У плашки меню: «сделать
опциональным / обязательным / переговоркой», «убрать». Точка на плашке —
занятость в выбранное время (цвет + подпись в title).

### «Лучшие варианты»
- Неделя (Пн–Пт) с переключателем «‹ неделя ›», старт — неделя выбранной даты.
- Ограничения галочками: «Не раньше 10:00», «Не трогать обед» (13–14),
  «Не в пятницу после 16:00», «Нужна свободная переговорка» (если есть переговорки).
  Состояние галочек запоминается в `prefs.sched_cons`.
- 6 вариантов, не пересекающихся в пределах дня. Карточка: день, время,
  свободная переговорка, счётчик «свободны 22 / 25», объяснение:
  «Заняты обязательные: …; под вопросом: …; опциональные заняты: …; в отпуске: …;
  нет данных: …; нарушено: раньше 10:00».
- Клик — подставляет время в «Начало/Конец», карточка выделяется.

### «По людям»
- Переключатель дня (Пн–Пт выбранной недели), колонки — получасы рабочего дня
  (`prefs.work_start..work_end`).
- Сверху строка «Все обязательные» (насыщенность = доля занятых), дальше группы
  «Обязательные», «Опциональные», «Переговорки», «Нет данных / рассылки»;
  группы сворачиваются.
- Встреча — рамка поверх сетки: тянется мышью (pointer events), клик по сетке
  ставит начало; клавиатура: ←/→ двигают рамку на 30 мин.
- Легенда: занят (заливка), под вопросом (штриховка), вне офиса (другая штриховка),
  нет данных (серый). Цвет никогда не единственный признак.

### Повестка
Блок «Повестка» над «Описанием»: пункты (название, минуты, ведущий из участников),
«+ пункт», шаблоны «Ретро», «Демо», «Дейли». Строка «N из M мин расписано» /
предупреждение, если больше длительности. При сохранении пункты вставляются в
начало описания нумерованным списком («1. Что получилось — 15 мин (Соколова М.)»).
При редактировании встречи повестка не парсится обратно (остаётся текстом в описании).

## Сервер (`webapp.py`)

1. **`people/schedule`** — `{who: [addr…], start: "YYYY-MM-DD", days: 5}` →
   `{items: [{address, name, freebusy: "…" (days×48 символов с 00:00 локального
   времени первого дня)}], unresolved: [...]}`. Внутри — `people.availability`
   пачками по 20 адресов, окно [start 00:00, start+days 00:00). Кэш по
   (acct, адреса, start, days) на 120 с. Ошибка сервера → `ok: false`, UI
   показывает фолбэк «только ваш календарь».
2. **Типы участников** — `events/create|update` принимают `attendees` как строки
   (как сейчас, = обязательный) или объекты `{address, type: "required"|"optional"|"resource"}`.
   Патч `_patch_attendee_types()` (по образцу `_patch_calendar_attendees`)
   оборачивает `calendar._attendees_block`, выставляя `AttendeeType` 1/2/3, и
   `_resolve_attendees`, чтобы тип не терялся при резолве. Оптимистичная запись
   в кэше календаря (`pending`/`overrides`) хранит тип.
3. **`prefs`**: новые ключи `rooms` (список `{address, name}`) и `sched_cons`
   (объект булевых), валидация в `update_prefs`.

## Клиент (`web/index.html`, `web/ui-kit/app.css`)

Чистые функции (тестируются в `tests/js/ui_logic.test.mjs`):
- `fbSlice(fb, day, ws, we)` → коды получасов рабочего дня.
- `rankSlots({people, dur, ws, we, cons, rooms})` → отсортированные варианты
  `{day, slot, reqBusy, reqTent, optBusy, oof, noData, rooms, pen, score}`;
  штраф: занятый обязательный 10, под вопросом 3, занятый опциональный 2,
  нарушение ограничения 6; варианты одного дня не пересекаются.
- `explainSlot(o)` → строка объяснения.

UI-код: `renderSchedPane`, `renderBest`, `renderPeopleGrid`, группы плашек,
повестка. Загрузка: скелетон сетки; ошибка — строка с «Повторить».
Перезапрос занятости — при изменении состава участников или недели (дебаунс 450 мс);
смена времени/длительности только пересчитывает рейтинг.

## Тесты

- JS: `fbSlice`, `rankSlots` (все свободны → лидер; ограничения сдвигают рейтинг;
  непересечение в пределах дня; «нет данных» не считается занятостью, но попадает
  в объяснение), `explainSlot`.
- Python: `_patch_attendee_types` даёт `AttendeeType` 2/3 для optional/resource и 1
  для строк; `people/schedule` режет на пачки по 20 и склеивает ответы (мок клиента);
  валидация новых `prefs`.
- Стенд: headless Chrome с подменённым API (как для 1.2.26) — открыть редактор,
  обе вкладки, перетащить рамку.
- Живая проверка на Alfa-Bank: встреча с опциональным участником и переговоркой,
  в Outlook у участника видно «необязательный».

## Не входит

Опрос по времени; раскрытие рассылок; часовые пояса участников; экран ответов
после отправки; предпросмотр приглашения; Android-специфика сверх адаптива.
