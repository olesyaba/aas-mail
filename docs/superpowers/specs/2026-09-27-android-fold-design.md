# AAS mail для Android (Samsung Galaxy Z Fold 8) — дизайн

Дата: 2026-09-27 · Статус: утверждён в чате, ждёт ревью спеки

## Цель

Личная Android-версия AAS mail с текущими возможностями macOS-сборки 1.2.19
(почта и календарь Alfa / Alfa-Seller поверх Exchange ActiveSync) для Fold 8:
удобно на внешнем (узком) и внутреннем (почти квадратном) экране, уведомления
о письмах и встречах при закрытом приложении.

**Сказано пользователем:** только для себя, APK ставится вручную; фон — уведомления
о письмах (~15 мин) + точные напоминания о встречах; раскладка — одна панель на
внешнем экране, список + письмо на внутреннем; вариант A (оболочка + тот же Python).

**Допущения:** сеть — та, что на телефоне (VPN/Karing для Alfa настраивается в
системе, не в приложении); точные размеры экранов Fold 8 неизвестны, раскладка
выбирается по ширине окна (внешний ≈400 CSS-px, внутренний ≈850–900).

**Критерии успеха**
1. Оба аккаунта: список писем, чтение, ответ/пересылка/отправка, вложения, календарь, RSVP — как на Mac.
2. Складывание/раскрытие не теряет открытое письмо и не перезагружает страницу.
3. Уведомление о новом письме приходит при закрытом приложении (задержка ≤ ~15 мин + Doze).
4. Напоминание о встрече за N минут (по умолчанию 5) с кнопкой «Подключиться».
5. macOS-сборка и все существующие тесты не меняют поведения.

**Не входит в v1:** Google Play, самообновление, виджеты, Wear OS, FCM-пуши,
биометрия на вход, свайп-жесты в списке, плавающий баннер встречи.

## 1. Архитектура

```
AAS mail.apk
  MainActivity (Kotlin) ── WebView → http://127.0.0.1:8780 (тот же web/)
  MailServer (Kotlin)   ── Chaquopy Python 3.12: webapp.py + bridge.py + vendor/outlook_activesync_mcp
  SyncWorker (WorkManager, 15 мин) ┐
  MeetingAlarms (AlarmManager)     ┴─ POST /api/* с X-Tok (runtime_token), как TrayAPIClient.swift
```

- Новый каталог `android/` в этом репозитории (Gradle + Kotlin + Chaquopy).
  `web/`, `webapp.py`, `bridge.py`, `vendor/` копируются в APK при сборке — без форка.
- Сервер запускается в процессе приложения (поток Python) и живёт, пока жив процесс; фоновый
  рефрешер сам затихает без активности UI (`_last_activity`), процесс в фоне завершает Android.
- `android/build_apk.sh` → `dist/AAS-mail-<ver>-android.apk`, прикладывается к релизу рядом с mac.zip.
- Сборка: Android SDK есть (`~/Library/Android/sdk`), нужна JDK 17+ (сейчас 15) — `brew install openjdk@17`.

**Правки общего кода (без изменения поведения на Mac):**
1. `_keychain_get/_keychain_set` (`webapp.py:196`): на Android — через мост Chaquopy в Kotlin-хранилище.
2. Пути: `EAS_BRIDGE_CONFIG`, `EAS_BRIDGE_DATA_DIR` → `filesDir` (уже поддерживается в `bridge.py`).
3. `/api/update` на Android: `{ok:false, error:"unsupported", url:<страница релиза>}`.
4. Мост уведомлений из JS: `window.AASNative?.notify(...)` рядом с существующим вызовом Swift.

## 2. Раскладка под Fold

| Ширина | Раскладка |
|---|---|
| ≥ 600px (внутренний) | Существующий режим ≤860px: папки — выезжающее меню, список + письмо. Добавить `env(safe-area-inset-*)`. |
| < 600px (внешний) | Новое: одна панель. Тап по письму → письмо на весь экран, системное «назад» → список. Шапка: ≡, точка аккаунта, лупа. «Написать» — плавающая кнопка снизу справа. Календарь — повестка дня. |
| `(pointer: coarse)` | Цели касания ≥ 44px. |

- Activity с `configChanges` (screenSize|smallestScreenSize|screenLayout|orientation) —
  WebView не пересоздаётся, срабатывает CSS; JS по ширине решает, какую панель показывать.
- Одна панель: класс `body.reading` + `history.pushState`, «назад» Android → `popstate`.
- Правки: `web/ui-kit/app.css` (блоки `max-width: 599px` и `pointer: coarse`), `web/index.html` (переключатель панелей).
  На Mac не срабатывают (мин. ширина окна 640px, указатель не coarse).

## 3. Уведомления и фон

**Новые письма:** `SyncWorker` (WorkManager, периодически 15 мин, требует сеть):
поднимает сервер при необходимости → по каждому аккаунту `POST /api/mail {action:"list", limit:20}` для Входящих →
новые непрочитанные `item_id` против сохранённых в SharedPreferences → уведомление
(🔴 Alfa / 🟢 Seller, отправитель, тема; группировка «N новых»; тап открывает письмо).
Пока приложение открыто — текущий автосинк `web/` и `AASNative.notify`. Бейдж на иконке — счётчик непрочитанных.

**Встречи:** при каждом синке `/api/events` на 24 ч → `AlarmManager.setExactAndAllowWhileIdle`
за N минут; лишние будильники снимаются. Правила — порт `TrayNotificationPlan.plan`
(пропуск отменённых и уже прошедших; id с префиксом аккаунта). Уведомление heads-up с кнопкой
«Подключиться», если есть ссылка.

**Разрешения при первом запуске:** `POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`,
исключение из оптимизации батареи (экран с одной кнопкой).

**Сбои сети:** синк молча пропускается; уведомление «нет связи с <аккаунт>» — только после 3 неудач подряд.

## 4. Пароли, данные, ошибки

- Настройка аккаунтов — существующий экран (`/api/account-config`). У телефона свой `device_id`
  и своё состояние синка; для Exchange это новое устройство.
- **Риск №1:** Exchange Alfa может поместить новое ActiveSync-устройство в карантин. Проверяется
  первым шагом плана (Python-клиент с телефона → FolderSync), до работы над UI.
- Пароли — `EncryptedSharedPreferences` (ключ в Android Keystore). Перенос из `config.json` работает как на Mac.
- Данные — `filesDir`; `android:allowBackup="false"`.
- Вложения: скачивание из WebView перехватывается, сохранение через Storage Access Framework; открытие — системный выбор приложения.
- Сервер: только `127.0.0.1`, `X-Tok` + `_guard` без изменений. WebView не уходит с localhost:
  внешние ссылки и ссылки встреч — через `Intent.ACTION_VIEW`.
- Python не стартовал → экран «Не удалось запустить» + «Отправить лог» (`eas-mail.log` через «Поделиться»).

## 5. Тесты

- Существующие `tests/run_tests.sh` (Python/JS/Swift) — зелёные.
- JS (`tests/js/ui_logic.test.mjs`): переключение одной панели и «назад».
- Python (`tests/python/test_logic.py`): выбор хранилища паролей на Android.
- Kotlin JUnit: порт `NotificationPlan` и сравнение новых писем по `item_id`.
- Вручную: эмулятор с профилем складного устройства (7.6" Fold-in) и реальный Fold 8 —
  складывание/раскрытие, уведомление о письме при закрытом приложении, будильник встречи, вложения.
